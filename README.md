# Camera Event Monitor

Прототип рабочего места оператора видеонаблюдения: анализ видеопотока с помощью YOLO, фиксация детекций и разбор событий через локальный веб-интерфейс Streamlit. Проект подготовлен на основе курсовой работы.

## Возможности

- Регистрация и вход в локальную учётную запись. Пароли хранятся как PBKDF2-SHA256 с индивидуальной солью.
- Обработка камеры по умолчанию через OpenCV и распознавание объектов пользовательской моделью YOLO.
- Проверка каждого третьего кадра с порогом уверенности 0,6.
- В основной версии — временной фильтр: окно 5 секунд, не менее 3 секунд наблюдений, детекция не менее 60% времени и интервал между сигналами от 5 секунд.
- Сохранение кадров и журнала событий, просмотр, отметки зелёным/жёлтым/красным и удаление событий.
- Отправка письма настроенному получателю через SMTP SSL. Настройки задаёт пользователь; автоматического обращения в экстренные службы нет.

## Переносимая сборка Windows

В [Releases](https://github.com/Himera2134567/camera-event-monitor/releases) доступен архив `CameraEventMonitor-Windows-x64.zip`. Распакуйте **всю папку**, затем запустите `CameraEventMonitor.exe`. Python и виртуальное окружение устанавливать не нужно. Папка `_internal` нужна для работы: перенос одного EXE без неё не поддерживается.

Приложение поднимает локальный интерфейс по адресу `http://127.0.0.1:8501`. Закройте окно запуска, чтобы остановить сервер. Для детекции нужна доступная камера; CPU-сборка не требует CUDA. Фактическая скорость зависит от процессора и камеры. Поддерживаемая цель сборки — Windows x64.

В сборку включена исходная обученная модель `models/best.pt`. Модель определяет распознаваемые классы и качество детекции; полноценной проверки точности на отдельном тестовом наборе в этой публикации нет.

## Настройки и данные

Скопируйте `.env.example` в `.env` рядом с EXE и при необходимости задайте:

| Переменная | Назначение |
| --- | --- |
| `MODEL_PATH` | Путь к весам YOLO; по умолчанию `models/best.pt` рядом с EXE. |
| `CAMERA_MONITOR_DATA` | Каталог данных; по умолчанию `%LOCALAPPDATA%/CameraEventMonitor`. |
| `CAMERA_MONITOR_PORT` | Порт локального интерфейса, по умолчанию `8501`. |
| `SMTP_SERVER`, `SMTP_PORT` | Почтовый сервер и SSL-порт. |
| `SMTP_USER`, `SMTP_PASS`, `SMTP_TO` | Учётные данные отправителя и адрес получателя. Без них отправка отключена. |

Данные новых запусков сохраняются в JSON и папке `events`. Личные базы пользователей, почтовые пароли, снимки камер, временные файлы Office и материалы с личными данными не публикуются. Старые pickle-базы не загружаются автоматически.

## Структура

| Файл | Назначение |
| --- | --- |
| `app.py` | Основной интерфейс и мониторинг с временной фильтрацией детекций. |
| `legacy_app.py` | Предыдущий вариант: сохраняет события по отдельным детекциям без временного фильтра. |
| `run.py` | Запускает локальный Streamlit-сервер и содержит проверку упакованных зависимостей. |
| `settings.py` | Переносимые пути, настройки `.env`, каталоги данных и модели. |
| `security.py` | Хеширование и проверка паролей локального прототипа. |
| `tools/convert_labels.py` | Приводит номера классов YOLO-разметки к `0` во всех каталогах `labels`. Изменяет выбранные файлы; работайте с копией датасета. |
| `build.py` | Сборка переносимой Windows-папки через PyInstaller. |
| `tests/test_core.py` | Проверки временного фильтра, паролей и конвертера на временных данных. |

`manage.py` из исходного архива не включён: связанный с ним Django-проект в архиве отсутствует; рабочий интерфейс реализован на Streamlit.

## Запуск из исходников и сборка

Для сборки нужен Python **3.12.10 или новее из ветки 3.12**, x64. В готовом EXE используется Python 3.12.14. Для CPU-версии сначала установите PyTorch и torchvision из официального CPU-индекса, затем остальные зависимости:

```powershell
python -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests
python run.py
```

Для запуска из исходников скачайте `best.pt` из релиза и поместите в `models`, либо задайте `MODEL_PATH`. Сборка: `python build.py`. После сборки скопируйте модель в `dist/CameraEventMonitor/models/best.pt` и `.env.example` рядом с EXE. Передавайте целиком папку `dist/CameraEventMonitor`.

В релизе приложен `requirements-tested.txt` с версиями окружения сборки и `SHA256SUMS.txt` с контрольными суммами.

## Проверки и ограничения

Выполнены тесты временного фильтра, паролей и конвертера, проверка регистрации и входа через Streamlit AppTest, проверка исходной модели на синтетическом кадре из EXE и HTTP-проверка локального интерфейса. Камера и отправка реальных писем при подготовке релиза не использовались.

Это локальный демонстрационный прототип. Мониторинг синхронный, хранение данных файловое; многопользовательское развёртывание, аудит доступа, промышленная надёжность и интеграции с системами охраны требуют отдельной доработки. Зависимости Ultralytics/PyTorch/OpenCV сохраняют свои лицензии; перед распространением производных продуктов проверьте их условия.
